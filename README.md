# 养老金计算器

一个在本机浏览器中使用的职工养老保险计算器。计算逻辑与 HTTP 服务端使用 Rust，界面使用无构建依赖的 HTML / CSS / JavaScript；JavaScript 不实现养老金公式。

**结果是达到领取条件后的月养老金情景估算，不是当前可提取余额，也不是社保经办核定待遇。**

## 浏览器本地计算（Rust / WebAssembly）

`dist/` 提供可直接托管的静态版本；养老金公式仍由同一个 `src/lib.rs` 编译为 WASM 执行，不由 JavaScript 重写。表单输入只存在浏览器内存中，不上传至计算 API，不持久化、不接第三方分析服务。

官方安装 Rust stable 后，安装官方编译目标并构建：

```sh
rustup target add wasm32-unknown-unknown
sh scripts/build-web.sh
node tests/wasm.cjs
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

打开 <http://127.0.0.1:8080>。Node.js 仅用于可选 WASM 回归测试，Python 仅用于上述静态预览；也可使用现有静态托管服务。不要直接双击 HTML。构建脚本不安装任何依赖工具，Cargo 按两份 `Cargo.lock` 获取 Rust 依赖。当前测试工具链为 Rust 1.99.1 stable；若需要固定编译器复现，可使用对应官方工具链版本。不同 Rust 版本可能产生不同 WASM 字节，但需保持测试结果一致。

`web/index.html` 是静态前端源，`frontend/index.html` 是本地 HTTP 版源；两者交互一致，仅计算调用方式不同。图标以 `frontend/` 为源，构建时同步到 `dist/`。修改公式只改 `src/lib.rs`；WASM wrapper 通过模块路径复用核心。

本仓库不包含任何托管平台账户配置、访问凭据或个人真实输入。静态文件本身不提供登录或访问控制，请按自己的托管环境配置隐私边界。

## 本地 Rust HTTP 服务启动

需要官方 Rust stable 工具链（包含 Cargo）。如尚未安装，请按 <https://rustup.rs/> 官方说明安装。

```sh
cargo test
cargo run --release
```

在浏览器打开 <http://127.0.0.1:3000>。不要直接双击 `frontend/index.html`，界面必须连接 Rust 服务才能计算。

默认只绑定本机回环地址。可通过 `PENSION_BIND` 指定其他本地端口：

```sh
PENSION_BIND=127.0.0.1:3100 cargo run --release
```

不要在没有认证和 HTTPS 防护的情况下绑定公网地址。默认不保存输入、不写访问日志、不加载第三方脚本、没有分析埋点及浏览器持久化；HTTP 响应使用 `no-store`。输入只发送给你启动的服务。如果自行部署到远程机器，输入将发送到那台服务器，不能再视为纯本机处理。

## 输入

四个主要输入：

1. 当前年龄。
2. 当前养老保险**个人账户储存额**，含已记账利息，不是统筹基金余额，也不是所有养老缴费之和。
3. 当前累计实际缴费月数。
4. 每月**计入个人账户的本金**。这是会累计进入养老个人账户本息的月入账值，不是单位与个人全部养老保险费，也不应重复包含已有记账利息。

可勾选按当地缴费基数上限入账。普通企业职工模型按个人账户入账比例 8% 反推缴费基数；单位统筹缴费不计入个人账户。灵活就业等其他参保类型不可将其总缴费比例直接当作入账比例。

### 为什么还需要高级参数

只有上述四个数，无法准确核定基础养老金。账户余额不能唯一还原历史缴费工资指数，所以高级参数必须核对：

- 历史平均缴费指数：默认 `1` 只是演示假设，可用权益记录中的核定数据替换。
- 养老金计发基数：与缴费基数上下限、指数参考工资**不是同一个概念**。初始 `12,577` 是演示值，不是已核实的退休计发基数。
- 缴费指数参考工资、缴费基数上下限：上海 2026 年 7 月起的缴费基数为 `7,546` 至 `37,731` 元，2025 年全口径城镇单位就业人员月平均工资为 `12,577` 元。它们不能直接证明未来养老金计发基数。
- 退休年月：优先于假设退休年龄。`63` 岁初始值只是演示，不适用于所有性别、出生年月和工种。本版不自动判定渐进式延迟退休时间，须按适用政策填入。
- 法定退休年月与核定最低缴费月数：弹性退休或延缴时可能与实际领取时点不同。经办核定的最低月数优先；否则使用所选退休年份与填写的法定退休年份中较早的一年，以区分弹性提前与延迟。缺少法定时点信息时仅作所选年份的条件性估算。
- 出生年月：可将年龄精度提高到月；不填时，整岁年龄仅是时间估算。
- 个人账户计发月数：整岁退休可使用政策表；非整岁、延缴等情况若无可靠规则，需填写经核定值，否则相关待遇显示“待核定”，不猜算。
- 未来缴费及参考工资增长率、计发基数增长率、个人账户记账利率：均为情景假设，缴费及参考工资增长率同时应用于未来月入账额、参考工资及缴费上下限。初始 `0%` 表示固定当前月入账额的静态比较，不代表未来实际增长或官方公布的利率。

所有初始年龄、余额及缴费记录是演示数据，不代表任何人的真实账户。计算月份与政策参数也可修改。

## 输出情景

- **现在停缴**：不再缴费，估算到退休领取时点的月养老金。未达到适用最低缴费月数时，月领按要求显示 `0`，同时显示缺口；这不表示个人账户被清零。
- **继续按月缴至最低月数**：不是一次性补缴假设。若需要在退休时点之后延缴，明确标注需要经办核定领取资格，待遇为待核定；手动填写最低月数或计发月数也不会自动授权延缴，不把数学可行性当成法律资格。
- **继续缴至退休**：按填写的退休时点计算。
- **再缴 5 / 10 / 15 / 20 年后停缴**：只列停止缴费时点不超过退休时点的情景。领取时点仍为满足条件的退休时点，不是缴满该年数后立即领取。

每个情景列出基础养老金、个人账户养老金、合计、累计缴费月数、领取时点、最低要求和账户余额。`0` 表示明确不满足最低月数；`待核定` 表示资格或关键参数不确定，两者不能混用。

## 政策口径与计算边界

按 2026 年 10 月核验的上海普通职工基础模型：

- 基础养老金：退休时计发基数 ×（1 + 平均缴费指数）÷ 2 × 缴费年限 × 1%。缴费月数折成年按现行上海规定保留四位小数。
- 个人账户养老金：退休时个人账户储存额 ÷ 对应计发月数。
- 最新上海规定对相关月养老金项目按角进位，实际实现和测试以 `src/lib.rs` 为准。
- 历史平均缴费指数与未来各月缴费指数按实际缴费月数加权；断缴月份不是额外缴费月数。
- 2030 年起最低缴费年限按规定逐年增加六个月，至 2039 年达到 20 年。程序不能永远固定使用 15 年。
- 将已知政策延伸到未来领取年份，是“未来规则不再改变”的假设，不是政策承诺。
- 预测账户利息只是简化情景，不替代社保机构实际逐年记账。
- 不包括过渡性养老金、视同缴费年限、特殊工种、提前退休、跨地区复杂核定或其他专项待遇。存在这些情况时，应使用经办机构核定数据和完整规则。

## API 与测试

- `GET /health`：服务健康状态。
- `GET /api/defaults`：返回完整演示输入。
- `POST /api/calculate`：接收输入 JSON，返回各情景、假设及警示；非法业务参数返回 422。

```sh
curl http://127.0.0.1:3000/health
curl http://127.0.0.1:3000/api/defaults > /tmp/pension-example.json
curl -H 'Content-Type: application/json' \
  --data-binary @/tmp/pension-example.json \
  http://127.0.0.1:3000/api/calculate
```

前端验收建议：检查低于最低月数显示 0、上限勾选、非法数值、距退休不足五年、非整岁退休未填计发月数显示待核定、补齐需延缴、手机窄屏等情况。运行测试和构建的实际结果应以当前环境日志为准，不因为源码附带测试就视为已经执行通过。

## 修改地区或政策

通过高级参数可以调整费率、参考工资和基数，但这**不足以自动支持任意地区**。本版上海的计发年限精度、金额进位和资格判断仍在 Rust 核心中；切换其他地区必须一起核对并修改 `src/lib.rs` 中的适用规则和对应测试，不能只改地区名称或基数。

## 回收年龄与实际自付回本

简化余额回收以当前含历史利息的账户余额加未来实际入账本金为比较额，不把未来记账利息计入成本。可另填历史个人实际缴费总额及当前月全部自付成本；后者默认等于月入账额，仅适用于普通单位职工，灵活就业应填全部自付。未来自付随缴费增长假设变化。

两者均以退休初始基础养老金加个人账户养老金的合计月领金额静态累计，向上取整到领取期数 N；首领月为第1期，累计覆盖成本的月份为首领月加 N−1（零成本为首领月）。结果不是投资收益率、寿命预测或精确到账日；未填出生年月仍有最多11个月误差。不考虑退休后调整、身故待遇、折现和机会成本。零养老金或待核定显示不适用；历史实际成本未填则不提供自付回本。

## 个人＋单位总缴费与时间边界

总成本 = 历史个人 + 历史单位 + 未来个人 + 未来单位。历史个人未填则以当前含息余额代理；历史单位未填则以历史个人实缴（未填时以余额）÷当前个人比例×当前单位比例代理。任何历史项缺失都显著标记“历史估算”；当前费率不能代表完整历史。未来单位费按当月缴费基数×单位费率计算，默认16%可调，并逐月累加。灵活就业已将全部费用计入个人自付时须将单位费率及历史单位额设0避免重复。单位缴费是总用工成本，不保证可一比一转为现金工资。

默认余额与累计已缴月数都截至计算起始月，未来从次月开始缴，包含退休当月。取消勾选表示两项截至上月，未来从起始月开始。退休当月审核通过、次月起领是模型假设；计发因子仍按退休当月年龄。
